create-data-luks.sh

Neuaufbau der verschlüsselten /data-Partition — LUKS2 + LVM + ext4

⚠ Destruktives Script — löscht das Zielgerät vollständig

Dieses Script löscht unwiderruflich den kompletten Inhalt von /dev/vda3 und baut darauf von Grund auf eine neue, verschlüsselte /data-Partition auf (LUKS2 → LVM → ext4). Es ist kein Routine- oder Wartungsscript, sondern ein einmaliger Neuaufbau-Vorgang — typischerweise beim Ersteinrichten eines Servers oder wenn /data bewusst komplett neu angelegt werden soll.

Gerät wird vollständig gelöscht (wipefs) Kein Undo Muss als root laufen

Was macht das Script?

Baut die Gerätekette /dev/vda3 → LUKS2-Verschlüsselung → LVM-Volume-Group vgdata → Logical Volume data → ext4-Dateisystem → Mountpoint /data komplett neu auf. Bestehende Daten auf /dev/vda3 (inkl. eines evtl. vorhandenen alten LUKS/LVM-Aufbaus) werden dabei entfernt. /dev/vda1 und /dev/vda2 bleiben unangetastet.

/dev/vda3 → LUKS2 (data_crypt) → LVM vgdata/data → ext4 → /data

Eingebaute Sicherheitsprüfungen

Das Script bricht sofort mit Fehler ab, wenn eine dieser Bedingungen nicht erfüllt ist — es läuft also nicht "versehentlich" auf dem falschen System:

  • Muss als root ausgeführt werden.
  • /dev/vda3 muss existieren und ein echtes Block-Gerät sein.
  • Das aufgelöste Gerät muss exakt /dev/vda3 sein (Schutz vor Symlink-Verwechslungen).
  • Das Root-Dateisystem darf nicht selbst auf vda3 liegen (verhindert das Formatieren der laufenden Systempartition).
  • Nach Anzeige des aktuellen Partitions-Layouts muss man zur Bestätigung exakt das Wort NEU eintippen — jede andere Eingabe bricht ab, ohne etwas zu verändern.
  • Am Ende wird geprüft, dass /data nach dem Neuaufbau leer ist (außer lost+found) — sonst Abbruch mit Fehler.

Ablauf

1
Sicherheitsprüfungen (siehe oben) + Anzeige des aktuellen Layouts + Bestätigungsabfrage NEU.
2
Benötigte Pakete installieren (cryptsetup, lvm2), falls noch nicht vorhanden.
3
Docker und GlusterFS werden gestoppt (falls aktiv), /data wird ausgehängt.
4
Ein evtl. vorhandenes altes LVM (vgdata/data) und LUKS-Mapping (data_crypt) werden entfernt, /dev/vda3 wird komplett bereinigt (wipefs -a).
5
LUKS2 wird neu erstellt (Passwort-Abfrage mit Bestätigung) und geöffnet.
6
LVM (Volume Group vgdata, Logical Volume data mit dem gesamten verfügbaren Platz) und darauf ein ext4-Dateisystem werden erstellt.
7
/etc/crypttab und /etc/fstab werden zuvor als Zeitstempel- Backup gesichert, dann um die neuen Einträge ergänzt (alte Einträge für data_crypt//data werden ersetzt).
8
/data wird gemountet, auf Leerheit geprüft, initramfs aktualisiert. Docker/GlusterFS werden absichtlich nicht automatisch wieder gestartet.

Verwendung

AufrufWirkung
sudo ./create-data-luks.sh Startet den interaktiven Neuaufbau. Zeigt zuerst das aktuelle Layout und fragt die Bestätigung NEU ab, bevor irgendetwas verändert wird. Danach folgt eine Passwort-Abfrage für die LUKS-Verschlüsselung.

Kein --dry-run vorhanden — die NEU-Bestätigung ist die einzige Sicherung vor versehentlicher Ausführung. Bricht ein Schritt unterwegs ab (set -euo pipefail), stoppt das Script sofort.

Nach dem Lauf

  • Das LUKS-Passwort wird bei jedem Boot benötigt (außer bei automatischem Entsperren via Keyfile/Netzwerk, das dieses Script nicht einrichtet).
  • Docker und GlusterFS müssen nach erfolgreichem Aufbau manuell wieder gestartet werden.
  • Vor einem reboot empfiehlt das Script selbst, crypttab, fstab und cryptsetup luksDump /dev/vda3 nochmal zu prüfen.
  • Backups der vorherigen /etc/crypttab und /etc/fstab liegen als *.backup.<timestamp> im selben Verzeichnis.

Dateien

Script: /mnt/storage/scripts/create-data-luks.sh
Zielgerät: /dev/vda3
Mountpoint: /data
Backups: /etc/crypttab.backup.<timestamp>, /etc/fstab.backup.<timestamp>
