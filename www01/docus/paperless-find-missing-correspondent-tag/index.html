Paperless-Find-Missing-Correspondent-Tag.sh

Findet Dokumente ohne passenden Korrespondenten-Tag in Paperless-ngx

Was macht das Script?

Viele Dokumente in Paperless tragen zusätzlich zum Feld Korrespondent auch einen gleichnamigen Tag (z. B. Korrespondent "Swisscom AG" und Tag "Swisscom"). Dieses Script findet Dokumente, bei denen keiner der vorhandenen Tags dem Korrespondenten ausreichend ähnlich ist — also vermutlich ein passender Tag fehlt.

Es ändert nichts in Paperless, sondern gibt nur eine Liste der betroffenen Dokumente aus — reines Analyse-/Aufräum-Werkzeug.

Verwendung

AufrufWirkung
Paperless-Find-Missing-Correspondent-Tag.sh Durchsucht alle Dokumente mit gesetztem Korrespondenten und listet die auf, bei denen kein Tag ähnlich genug ist (Standard-Schwelle: 70 %).

Keine Parameter, keine Konfigurationsdatei — die Schwelle (70 %) ist fest im Script hinterlegt.

Wie wird ähnlich erkannt?

Korrespondent-Name und jeder Tag-Name des Dokuments werden normalisiert (Kleinschreibung, Sonderzeichen/Leerzeichen entfernt) und paarweise auf Textähnlichkeit verglichen. Der ähnlichste Tag wird ermittelt; liegt dessen Ähnlichkeit unter der Schwelle von 70 % (oder existiert gar kein Tag), gilt das Dokument als «auffällig» und wird in der Ausgabe gelistet.

Korrespondent "Swisscom AG" + Tag "Swisscom" → ähnlich genug Korrespondent "Viac" ohne passenden Tag → wird gelistet

Ausgabe lesen

Pro auffälligem Dokument werden angezeigt:

  • Dokument-ID und Titel
  • Name des zugewiesenen Korrespondenten
  • Alle aktuell gesetzten Tags des Dokuments
  • Der ähnlichste vorhandene Tag samt Prozentwert (oder «kein Tag», falls das Dokument gar keine Tags hat)

Am Ende folgt eine Zusammenfassung mit der Gesamtanzahl gefundener Dokumente und dem verwendeten Schwellenwert.

Das Script selbst legt keine Tags an oder ändert Dokumente — die gefundenen Fälle müssen manuell in Paperless nachgepflegt werden (z. B. passenden Tag ergänzen).

Voraussetzungen & Ausführungsort

  • Muss direkt auf dem Paperless-Docker-Host ausgeführt werden (wechselt intern nach /opt/paperless und ruft docker compose exec webserver ... auf) — kein Aufruf per API von einem anderen Rechner aus möglich.
  • Der Paperless-Container (webserver) muss laufen.
  • Keine eigenen Credentials nötig — das Script läuft direkt in der Paperless-Django-Shell im Container und nutzt dessen interne Datenbankanbindung.
