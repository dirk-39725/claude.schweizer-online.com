git-autopush.sh

Automatisches Commit & Push aller Änderungen im Scripts-Repository

Was macht das Script?

Wird typischerweise per Cronjob regelmäßig ausgeführt und sichert so änderungen am Scripts-Verzeichnis automatisch als Git-Historie: Es prüft, ob es im Repository Änderungen gibt, und falls ja, werden alle Änderungen committet und gepusht.

git add -A git commit git push

Hinweis: Es gibt eine zweite, gleichnamige Variante unter /mnt/storage/www/git-autopush.sh, die dasselbe Prinzip auf das Webseiten-Repository (/mnt/storage/www) anwendet — beide Scripts sind unabhängig voneinander und sichern jeweils ihr eigenes Repository.

Ablauf

1
Wechselt ins Repository-Verzeichnis /mnt/storage/scripts.
2
Prüft per git status --porcelain, ob es überhaupt Änderungen gibt — falls nicht, endet das Script sofort ohne Aktion.
3
Bei Änderungen: git add -A, Commit mit automatischer Nachricht («Automatisches Backup <Datum/Uhrzeit>»), dann git push.
4
Schlägt irgendein Schritt fehl, wird sofort per Pushover benachrichtigt (inkl. Zeile und Exit-Code des Fehlers), das Script bricht ab.

Verwendung

AufrufWirkung
./git-autopush.sh Einmaliger Lauf — committet/pusht bei Bedarf. Kein Parameter, kein --dry-run.

Gedacht für regelmäßigen Cron-Betrieb, nicht für interaktive Einzelaufrufe mit Auswahl, was committet wird — es wird immer alles hinzugefügt.
