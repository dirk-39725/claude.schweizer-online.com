manage-server-user.sh

Benutzer identisch auf mehreren Servern anlegen, ändern oder löschen (per SSH)

⚠ "delete" löscht den User inkl. Home-Verzeichnis

Die Aktion delete führt auf jedem Zielserver ein userdel -r aus — das entfernt den Benutzer und sein komplettes Home-Verzeichnis unwiderruflich, auf allen angegebenen Servern. Vor einem echten delete-Lauf lohnt sich immer erst ein --dry-run.

delete = userdel -r (kein Undo) --dry-run verfügbar

Was macht das Script?

Verwaltet einen bestimmten Linux-Benutzer identisch auf mehreren Servern gleichzeitig — per SSH als root. Drei Aktionen stehen zur Verfügung:

create Legt den User an (falls er fehlt), verteilt den SSH-Key und setzt ein zufälliges Passwort.
modify Verteilt den aktuellen SSH-Key neu und setzt ein neues, zufälliges Passwort (legt den User bei Bedarf ebenfalls an).
delete Löscht den User inkl. Home-Verzeichnis von den Zielservern.

Eingebaute Absicherungen

  • root kann niemals als Zielbenutzer verwendet werden — das Script bricht sofort ab.
  • Der neue User bekommt kein sudo.
  • Passwörter werden pro Server zufällig und unterschiedlich gesetzt, aber nirgends ausgegeben oder gespeichert — Login funktioniert ausschließlich über den SSH-Key.
  • Der SSH-Key ist für alle Server identisch, wird im Verzeichnis des Aufrufs (nicht im Script-Verzeichnis) als <username>_ed25519(.pub) abgelegt und bei folgenden Läufen wiederverwendet.
  • Verbindung zu den Servern läuft als root per SSH — das Script selbst muss daher ebenfalls als root gestartet werden.
  • --dry-run zeigt pro Server exakt das Remote-Kommando an, das ausgeführt würde, ohne sich wirklich zu verbinden oder etwas zu ändern.

Verwendung

AufrufWirkung
manage-server-user.sh create deploy --all Legt User deploy auf allen Servern aus der Konfigurationsdatei an.
manage-server-user.sh delete deploy srv11.opn.ds srv12.opn.ds Löscht User deploy inkl. Home-Verzeichnis, aber nur auf den beiden genannten Servern.
manage-server-user.sh modify deploy --all --dry-run Zeigt nur an, was bei einer Schlüssel-/Passwort-Rotation auf allen Servern passieren würde — ändert nichts.

Allgemeine Form: manage-server-user.sh <create|modify|delete> <username> (--all | <server1> [<server2> ...]) [--dry-run]

--all und eine explizite Serverliste schließen sich gegenseitig aus. Server können einen abweichenden Port per host:port haben.

Konfiguration

Die Serverliste steht in einer Konfigurationsdatei, eine Server-FQDN pro Zeile, optional mit :port (Default 22). Kommentare mit #, Leerzeilen werden ignoriert: 

srv11.opn.ds
srv12.opn.ds:2222

Häufige Fragen

Wo liegt der erzeugte SSH-Key?

Im Verzeichnis, aus dem das Script aufgerufen wurde (nicht im Script-Verzeichnis selbst), als <username>_ed25519 und <username>_ed25519.pub. Bei create/modify wird ein vorhandenes Schlüsselpaar wiederverwendet, damit der Key auf allen Servern identisch bleibt.

Wie melde ich mich als der neue User an?

Ausschließlich per SSH-Key (ssh -i <username>_ed25519 <username>@<server>) — ein Passwort-Login ist nicht vorgesehen, das gesetzte Zufallspasswort wird nirgends ausgegeben.

Ein Server aus --all ist nicht erreichbar — was passiert?

Das Script fährt mit den restlichen Servern fort und meldet am Ende, bei welchen Servern die Aktion fehlgeschlagen ist (Exit-Code ungleich 0).
