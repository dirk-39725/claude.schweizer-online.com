find-and-run-backup.sh

Backup-Orchestrator — führt ein Backup-Script parallel auf mehreren Servern per SSH aus

Was macht das Script?

Liest eine feste Liste von Server:Pfad1,Pfad2,...-Zielen und führt auf jedem Zielserver ein Backup-Script (SCRIPT, Default .autobackup) aus — einmal pro Server, mit allen Pfaden dieses Servers als Parameter. Mehrere Server werden dabei parallel bearbeitet (bis zu MAX_PARALLEL_SERVERS gleichzeitig), die Pfade eines einzelnen Servers laufen dagegen immer sequenziell nacheinander.

Ist der Servername identisch mit dem Hostnamen des ausführenden Rechners, läuft das Backup-Script lokal ohne SSH — so kann der Orchestrator-Host sich selbst über dieselbe Zielliste mitsichern.

Automatisches Deployment des Backup-Scripts

Existiert SCRIPT auf einem Zielserver noch nicht, wird es aus einer lokalen TEMPLATE-Datei dorthin kopiert, ausführbar gemacht und direkt ausgeführt. Ist TEMPLATE neuer als die bereits am Ziel liegende Version (Vergleich der Änderungszeit), wird sie automatisch aktualisiert — ohne dass dafür ein eigenes Flag nötig ist.

Voraussetzung für den Zeitvergleich ist einigermassen synchrone Uhrzeit zwischen Orchestrator und Zielservern (NTP).

Verwendung

OptionBedeutung
--targets-file DATEI Externe Datei mit Backup-Zielen statt der TARGETS_LIST aus der Konfiguration (für einen einzelnen Lauf).
--destination DIR Wird unverändert als Parameter an das Backup-Script auf dem Server durchgereicht (Standard: /mnt/storage/server-backups).
--script NAME Name des auf dem Ziel auszuführenden Scripts (Default: .autobackup).
--deploy-dir DIR Zielverzeichnis auf dem Server, in das das Script kopiert wird (Default: /tmp).
--template NAME Name der Template-Datei im Verzeichnis dieses Scripts.
--ssh-user USER SSH-User für die Verbindung (Default: root).
--max-parallel N Wie viele Server gleichzeitig bearbeitet werden (Default: 4).
--dry-run Kein Deployment/Update auf den Zielen, aber ein echter SSH-Login je Server: existiert das Script dort schon, wird es einmal mit --dry-run aufgerufen (kein rsync, kein Docker-Stop — nur simuliert). Bestätigt so Erreichbarkeit/Credentials, ohne ein echtes Backup auszulösen.
-h, --help Zeigt alle Optionen inkl. aktueller Defaults an.

Format der Zielliste

Eine Zeile pro Server, Pfade kommagetrennt (in TARGETS_LIST der Konfigurationsdatei oder in einer per --targets-file angegebenen Datei; dort sind zusätzlich #-Kommentare erlaubt): 

srv1.opn.ds:/etc,/opt
srv2.opn.ds:/etc,/data
srv12.opn.ds:/data/dbs

Ungültige Zeilen/Pfade (fehlender Doppelpunkt, leerer Server, nicht-absoluter Pfad) werden übersprungen und als Fehler vermerkt, statt den gesamten Lauf abzubrechen.

Benachrichtigung

Am Ende jedes Laufs wird — sofern PUSHOVER_BIN konfiguriert ist — immer eine Pushover-Meldung verschickt: bei Fehlern/Warnungen mit hoher Priorität und Zusammenfassung aller Probleme, bei erfolgreichem Abschluss (auch im Dry-Run) eine Erfolgsmeldung inkl. Laufzeit.
